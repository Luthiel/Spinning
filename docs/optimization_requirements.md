### 1.2 当前执行引擎问题

```go
// 当前只是模拟执行
delay := time.Duration(300+rand.Intn(1200)) * time.Millisecond
select {
case <-ctx.Done():
    ...
case <-time.After(delay):
}
// 10% 随机失败
if rand.Float64() < 0.10 {
    // 返回模拟错误
}
```

- Skill 实际未被调用，只是 sleep 后返回 mock 数据
- 没有真正的错误处理和重试机制
- 无执行历史追踪（只保存到内存）
- 无断点续跑能力

## 2. 优化需求

### 2.1 执行引擎增强 [优先级: 高]

#### 2.1.1 真实 Skill 执行

```
需求:
- 支持调用外部 Skill 服务（HTTP/gRPC）
- Skill 配置中增加 endpoint 字段
- 支持认证（API Key/Bearer Token）
- 超时控制（默认 30s，可配置）

技术方案:
- 新增 SkillExecutor 接口
- 实现 HTTPExecutor / gRPCExecutor
- 执行器从 Skill 配置读取 endpoint
```

#### 2.1.2 错误处理与重试

```
需求:
- 节点失败时自动重试（默认 3 次）
- 可配置重试次数和间隔
- 失败策略：停止 / 跳过 / 回退

技术方案:
- 新增 RetryConfig 字段到节点配置
- 实现指数退避重试
- 支持失败分支定义
```

#### 2.1.3 断点续跑

```
需求:
- 执行中断后可从断点恢复
- 支持从指定节点开始执行
- 已执行节点结果可复用

技术方案:
- 持久化执行状态到数据库
- 执行记录表：execution_id, node_id, status, output
- Resume API: POST /api/executions/:id/resume
```

### 2.2 可观测性增强 [优先级: 高]

#### 2.2.1 执行历史与追踪

```
需求:
- 执行记录持久化存储
- 执行详情可查询（节点输入/输出/耗时）
- 执行统计（成功率/平均耗时/峰值耗时）

技术方案:
- 新增 FlowExecution 表
- 新增 NodeExecution 表
- 新增 ExecutionLog 表（已有，需持久化）
- GET /api/executions 列表接口
- GET /api/executions/:id 详情接口
```

#### 2.2.2 性能指标

```
需求:
- 流程级别：总耗时/节点数/并行度
- 节点级别：耗时/成功失败/重试次数
- 趋势图：近 7 天执行趋势

技术方案:
- 新增 metrics 端点
- 计算聚合指标
- 前端新增统计面板
```

#### 2.2.3 结构化日志

```
需求:
- 日志持久化存储
- 日志级别过滤（debug/info/warn/error）
- 日志搜索

技术方案:
- ExecutionLog 持久化到数据库
- 日志查询 API
- 前端日志面板增强
```

### 2.3 协作功能 [优先级: 中]

#### 2.3.1 多用户支持

```
需求:
- 用户注册/登录
- 个人流程空间
- 团队共享流程

技术方案:
- 新增 User 表
- 流程增加 owner_id 和 team_id
- 权限级别：owner/editor/viewer
```

#### 2.3.2 流程版本控制

```
需求:
- 流程历史版本
- 版本对比（diff）
- 回滚到历史版本

技术方案:
- 新增 FlowVersion 表
- 自动保存版本快照
- Version API
```

#### 2.3.3 流程模板市场

```
需求:
- 公开模板库
- 模板评分/收藏
- 一键克隆

技术方案:
- 新增 Template 表（is_public 字段）
- 模板搜索/推荐
- 克隆功能
```

### 2.4 触发器与集成 [优先级: 中]

#### 2.4.1 Webhook 触发

```
需求:
- 支持 Webhook 触发流程执行
- 签名验证
- 触发事件日志

技术方案:
- POST /api/webhooks/:flow_id
- HMAC 签名验证
- WebhookExecution 表
```

#### 2.4.2 定时任务

```
需求:
- cron 表达式调度
- 支持间隔执行
- 执行历史

技术方案:
- 新增 Schedule 表
- 后台调度器（内嵌或独立）
- Schedule API
```

#### 2.4.3 外部事件驱动

```
需求:
- 消息队列集成（Kafka/RabbitMQ）
- 事件订阅

技术方案:
- 事件监听器接口
- 实现 Kafka / RabbitMQ 消费者
```

### 2.5 扩展性增强 [优先级: 低]

#### 2.5.1 自定义节点

```
需求:
- 用户自定义节点类型
- 节点配置面板
- JavaScript 脚本节点

技术方案:
- 节点类型注册表
- 脚本执行沙箱（wasm 或isolate）
```

#### 2.5.2 插件系统

```
需求:
- Skill 插件市场
- 第三方 Skill 接入

技术方案:
- 插件接口定义
- 动态加载
```

## 4. 技术债务

| 问题 | 影响 | 建议 |
|------|------|------|
| SQLite 并发写入 | 生产环境性能 | 考虑 PostgreSQL |
| 前端状态管理 | 复杂流程时卡顿 | 考虑分页/虚拟化 |
| 无单元测试 | 维护困难 | 补充测试覆盖 |
| 硬编码配置 | 部署不灵活 | 完善配置系统 |

---

## 5. 优先级建议

建议按以下顺序实施：

1. **执行引擎增强** - 核心功能，必须实现真实执行能力
2. **可观测性** - 调试和问题排查必需
3. **触发器** - 让流程可被自动化触发
4. **协作功能** - 团队使用必需
5. **扩展性** - 后期考虑
